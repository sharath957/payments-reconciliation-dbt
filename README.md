# payments-reconciliation-dbt

Practice project: reconcile clinic invoices → card charges → refunds → processor payouts on Snowflake with dbt, and catch planted data-quality defects with tests.

All data is synthetic, generated by `scripts/generate_data.py` (seeded, so it's reproducible).

## Source data

| File | Grain | Rows |
|---|---|---|
| `data/raw_clinics.csv` | clinic | 40 |
| `data/raw_invoices.csv` | invoice | 14,893 |
| `data/raw_charges.csv` | charge attempt | 14,696 |
| `data/raw_refunds.csv` | refund | 546 |
| `data/raw_payouts.csv` | bank payout | 4,891 |
| `data/raw_payout_items.csv` | line in a payout (charge +, fee −, refund −) | 28,329 |
| `seeds/fee_rate_card.csv` | card brand (contracted fees, loaded via `dbt seed`) | 4 |

Period: invoices Apr 1 – Sep 30, 2026. Data extracted as of 2026-10-06 00:00 UTC. All timestamps are UTC.
Payouts settle 2 business days after the charge/refund (clinic-local date), so successful charges from Oct 2 onward are legitimately unpaid at extract time.

## Load to Snowflake

1. Run `snowflake/01_setup_and_load_raw.sql` in a Snowsight worksheet down to step 4.
2. Upload the 6 files in `data/` to the `RAW_STAGE` stage.
3. Run steps 5–6 and check the row counts.

## Regenerate

```
python3 scripts/generate_data.py
```

Standard library only, Python 3.9+.

## Answer key

`_answer_key/defect_manifest.csv` lists every planted defect by record id. It is git-ignored on purpose: write the tests first, then score them against it.
